# CLAUDE.md — CrashCart: Sentry-compatible backend in Go + Postgres

Sibling repo: **crashcart-cloudflare** (TypeScript / Workers / D1 + R2) keeps the same
product on the Cloudflare stack. Behavior is equivalent; the API and schema here were
redesigned for Go + Postgres and are NOT wire-compatible with that repo.

## Stack

- **Go 1.24+**, `net/http` ServeMux (Go 1.22 patterns), `log/slog`
- **Postgres** via pgx/v5; queries generated by **sqlc** (`internal/db/queries/*.sql` →
  `internal/db/sqlc`); migrations embedded + applied at startup
- **Viewer**: **templ** components + htmx + shadless/Tailwind v4, served by the same binary
- Schedulers (retention, alerts) are goroutine tickers inside `serve` — no cron

## Architecture

```
Sentry SDK → POST /ingest | /api/{project}/envelope/   (ingest package → one tx)
Browser    → GET /  /dashboard  /events/{id}/detail  /settings   (web package, htmx)
Program    → GET /api/events|stats/*|issues|alerts|symbols, POST /api/symbolicate
```

### Storage

Everything lives in Postgres (no object store): `events.payload` is JSONB, TOAST handles
large payloads; symbol files are `bytea` in `symbol_files`. Tables: `events`,
`user_devices`, `hourly_stats`, `issues`, `releases`, `release_health`, `alert_types`,
`symbol_files`, `schema_migrations`.

- `events.occurred_at TIMESTAMPTZ` + `(occurred_at DESC, id DESC)` index — no
  timestamp-in-PK trick. Partial indexes on device/user/error_type/release/fingerprint.
- `events.tags JSONB` object with a GIN (`jsonb_path_ops`) index → tag filters are
  `tags @> '{"k":"v"}'`.
- `events.fingerprint` links to `issues` → issue drill-downs are exact joins.
- Fingerprint = sha256(platform:errorType:last-5-frames file:function)[:16] hex; the SDK's
  `fingerprint` array wins when present.

### Ingest (hot path)

`sentry.Parse` → sampling → `ingest.build` folds per-key aggregates in Go → **one
transaction**: `COPY events` (sqlc `:copyfrom`) + pgx batches (sqlc `:batchexec`) for
`user_devices`, `hourly_stats`, `releases`, `issues`, `release_health`. Aggregate keys are
sorted before the batch so concurrent envelopes take row locks in the same order.
Envelope cap 2 MB / 500 events; gzip + deflate accepted.

### Query path

`store` wraps sqlc with domain filters. `ListEvents` is one static sqlc query where every
filter is optional (`$n IS NULL OR col = $n`, `cardinality($levels) = 0 OR …`,
`tags @> $tags`). Zero-filled series (`CrashTimeline`, `Volume`) come from `timerange`
slots. The viewer calls `store` directly — never HTTP to itself.

## Key decisions

- **Why one tx per envelope?** Postgres makes logs + aggregates atomic for free; no
  "aggregate drift" and no partial-failure isolation code.
- **Why in-memory rate limiting?** Single process; a table would cost a write per request.
  Keys are SHA-256 digests of the credential (or the client IP).
- **Why both `/ingest?token=` and `/api/{project}/envelope/`?** The second is what Sentry
  SDKs derive from a DSN, so `http://TOKEN@host/1` works without a custom transport. The
  token is read from `?token`, `?sentry_key` or `X-Sentry-Auth`.
- **Why templ?** Type-checked HTML with the same htmx attributes as the TS version;
  `{ children... }` composition mirrors JSX. `templ.Attributes` spreads carry the
  `hx-*` sets (`hxNav`, `hxRowNav`, `hxDetail` in `format.go`).
- **Why keep shadless + Tailwind?** Same design system as the Cloudflare viewer: slots
  (`data-slot="button|card|badge|table|sheet|switch|alert|input|native-select"`), severity
  token ramp (`--level-*` → `--chart-*`), explicit colors per slot × variant, `color-scheme`
  per theme. Source `internal/web/styles/app.css`; compiled artifact
  `internal/web/assets/app.css` is committed (`make css` to rebuild; needs `npm install`).
- **Charts**: server embeds `{labels, series:[{name, token, data}]}` on
  `<canvas data-chart>`; `app.js` renders with Chart.js using the live theme tokens.
  Labels are already localized (`cc-tz` cookie → hour labels), so the API stays UTC.

## Auth & limits

- `/api/*` — `Authorization: Bearer` against `API_KEYS`; `/ingest` — `INGEST_TOKEN`.
  Unset = open (dev).
- Rate limit after auth (only authenticated callers create buckets), fixed 60 s windows,
  `X-RateLimit-*` headers, `RATE_LIMIT=0` disables.
- CORS only on `/ingest` + `/api/*`. HTML routes are same-origin; `PATCH
  /settings/alerts/{type}` requires the `HX-Request` header (CSRF guard).
- `PII_REDACT=true` gates all redaction (message, tags, user id); off by default.

## Conventions

- Regenerate after editing: `sqlc generate` (queries/schema), `templ generate` (.templ).
  `make generate` does both. Generated files are committed.
- Never hand-write SQL in Go outside `internal/db/queries` (migrations + `db.Migrate` are
  the only exceptions).
- Nullable text columns are `*string` (sqlc `emit_pointers_for_null_types`);
  `TIMESTAMPTZ` → `time.Time` / `*time.Time`; `JSONB` → `json.RawMessage`.
- API JSON is snake_case (sqlc `json_tags_case_style: snake`); times RFC3339 UTC.
- Viewer URL state: `win`, `anchor`, `page`, `crash`, `err`, `release` + filter keys
  (`q`, `level`, `error_type`, `user_id`, `device_id`, `device_model`, `os_version`,
  `error_location`, `fingerprint`, custom tag keys). `ViewState.With*` return copies.
- Tests: unit tests everywhere; `internal/server/server_test.go` is the end-to-end suite
  (ingest → API → viewer → retention → alerts) and needs `TEST_DATABASE_URL`.

## Retention

Hourly (`RETENTION_INTERVAL`), cutoff `now - RETENTION_DAYS`: events deleted in batches of
5000 by `occurred_at`; `hourly_stats` by hour; `issues` by `last_seen`; `user_devices` by
`last_seen` (refreshed lazily at ingest, ≤ once/day/pair); `release_health` by day.

## Terminology

See GLOSSARY.md. "Release" not "app version"; "Event" not "log"; "Issue" not "error
group"; "Platform" not "OS"; "Sentry SDK compatible" not "Sentry backend".
